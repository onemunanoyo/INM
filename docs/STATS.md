# INM Statistical Uncertainty

INM does **not** require a fixed number of benchmark items.

Each released benchmark version freezes a reviewed item set. Later versions may add new items in order to improve topical coverage and reduce statistical uncertainty.

The preferred rule is therefore:

> Add reviewed, well-sourced items when they improve coverage or reliability; do not add low-quality items merely to reach a round number.

---

## Why item count matters

If benchmark items are treated as independent Bernoulli trials, an observed accuracy `p` over `n` items has approximate standard error

```text
SE = sqrt(p * (1 - p) / n)
```

The largest standard error occurs near `p = 0.5`.

For a 95% normal-approximation interval, the corresponding worst-case margin of error is approximately

```text
MOE95 = 1.96 * 0.5 / sqrt(n)
```

This gives the following rough scale:

| Scored items | Worst-case SE | Worst-case 95% margin of error |
|---:|---:|---:|
| 25 | 10.00 pp | ±19.60 pp |
| 50 | 7.07 pp | ±13.86 pp |
| 100 | 5.00 pp | ±9.80 pp |
| 200 | 3.54 pp | ±6.93 pp |
| 400 | 2.50 pp | ±4.90 pp |
| 800 | 1.77 pp | ±3.46 pp |
| 1600 | 1.25 pp | ±2.45 pp |

`pp` means percentage points.

These values are deliberately conservative because they use the maximum-variance case `p = 0.5`.

---

## Wilson confidence interval

INM reports a Wilson score 95% confidence interval in addition to the simple standard error.

The Wilson interval is preferred over the naive `p ± 1.96 * SE` interval, especially when:

- the number of items is small;
- accuracy is close to 0% or 100%;
- category-level subsets contain relatively few items.

Use:

```bash
python scripts/stats.py --n 100 --correct 72
```

or:

```bash
python scripts/stats.py --n 100 --accuracy 72
```

`--accuracy` accepts either a fraction (`0.72`) or a percentage (`72`). Because benchmark outcomes are discrete, an accuracy supplied directly is converted to the nearest integer number of correct items.

---

## Reference table

To calculate the worst-case uncertainty for arbitrary benchmark sizes:

```bash
python scripts/stats.py --reference 25 50 100 200 400 800
```

The script prints the worst-case standard error and 95% margin of error for each item count.

---

## Runner result files

The statistics script can read the JSONL output generated by the INM runner:

```bash
python scripts/stats.py --results results/tmp/<run>.jsonl
```

It reports:

- overall accuracy;
- overall standard error;
- Wilson 95% confidence interval;
- worst-case 95% margin of error for the observed sample size;
- the same statistics by category;
- the same statistics by difficulty when difficulty metadata is available.

Rows where `correct` is not a boolean value, such as provider errors, are excluded from the scored sample size.

---

## Important limitation: INM items are not truly independent

The binomial calculations above are an approximation.

Benchmark questions can be correlated. For example, several questions may depend on the same underlying fact, scene, character, quote, or source. Ten differently worded questions about one fact do not contain the same statistical information as ten genuinely different knowledge targets.

This means that simply increasing `n` does not automatically produce the effective sample size implied by the binomial formula.

INM should therefore expand along **knowledge coverage**, not only raw item count.

Examples of distinct coverage dimensions include:

```text
work_metadata
chapter_cast
character_alias
relationships
chapter_structure
quote_authenticity
quote_completion
source_attribution
```

When possible, benchmark authors should avoid creating many near-duplicate items whose answers depend on exactly the same fact.

---

## Interpreting model differences

Small score differences should not automatically be treated as meaningful.

For example, a four-percentage-point gap on a small category containing only 25 items may be dominated by item sampling noise and by the particular facts chosen for that category.

When comparing models, report at minimum:

- benchmark version;
- total scored item count;
- category-level item counts;
- observed accuracy;
- Wilson 95% confidence interval;
- evaluation configuration.

Repeated runs may additionally be useful for models or inference settings with stochastic generation. Run-to-run variance is a separate source of uncertainty from finite benchmark item count.

---

## Release policy

INM versions are intended to be versioned and extensible rather than fixed to a predetermined number of questions.

Before a release:

1. candidate items are reviewed and sourced;
2. ambiguous or low-quality items are removed;
3. the accepted item set is frozen;
4. the release receives a version identifier;
5. later additions are made in a later version rather than silently changing the released set.

Scores should always be reported together with the exact INM version.
